# AIXO — evidence-grounded learning experiments

**Stage: independent source not yet published; existing work is retained inside archived IXO source.**

AIXO explores experiments, outcome evaluation, world logs and learning *proposals*. It can compare ideas or methods against recorded examples while IXO retains program execution permissions and Hermes retains factual-memory acceptance. AIXO is not another spelling of IXO or a general-intelligence claim.

## Boundaries

- Source events carry exact IDs, versions, origin and byte-integrity evidence.
- Experiments distinguish training/evaluation items from independent holdouts.
- Proposed improvements are hypotheses, not verified model self-improvement.
- Claims can be rejected, amended or superseded without deleting evidence.
- AIXO does not authorize a second write path into Hermes or execute commands.

## What can be checked now?

The owner-held IXO v0.4.1 engineering archive contains an AIXO Python engine, unit tests and DSOE evidence handoff boundary. The **entire archive** passed 152 unit tests in an isolated Linux run on 2026-11-20. AIXO's standalone test number, native host acceptance and model learning improvement **have not** been established by this repository.

The independent repo was empty before this identity record. We will not copy a partial engine out of its true owner just to inflate the code count.

## First publication gate

1. Identify the exact archived AIXO version and current native owner adapter.
2. Preserve source history and any third-party attributions.
3. Extract only a genuinely separable experiment/evaluation contract.
4. Prove that holdout labels and claim origins cannot be overwritten by an evaluator.
5. Run independent negative tests, then publish reviewed source and a reproducible CLI demo.

The byte-first curriculum, Glimmer observer and Trainer model remain separate research threads. They can supply bounded experiments but do not automatically become AIXO production capabilities.
